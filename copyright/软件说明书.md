# 兵工铸魂·智绘易学AI思政教学应用软件 V1.0 软件说明书

## 一、软件概述

兵工铸魂·智绘易学AI思政教学应用软件 V1.0（以下简称“本软件”）面向兵工院校思政教育场景，以“测评—画像—推荐—学习—反馈—研判”为主线，把思政成长画像测评、兵工案例学习、每日问题、AI 学习助手与教师、学校两端的数据统计连接起来。

本软件由学生端、教师端与管理端组成。学生完成八维思政画像测评后，系统根据作答计算画像类型并推荐兵工案例；教师可查看所带学生的画像与学习行为，学校管理员可查看学院层面的群体统计。所有账号、测评与行为数据均保存在数据库中，不使用本地模拟名单。

本软件为沈阳理工大学装备工程学院教学试点应用，软件版本为 V1.0。

## 二、运行环境

### 2.1 服务端

- 操作系统：支持 Node.js 的 Linux、Windows 或 macOS
- Node.js：20 及以上版本
- 数据库：Supabase PostgreSQL（启用行级安全策略）
- 部署平台：Vercel，前端静态页面与 Serverless Functions 同域部署
- 网络：需要能够访问 Supabase 与 AI 服务接口

### 2.2 客户端

- 浏览器：Chrome、Edge、Firefox、Safari 等现代浏览器
- 屏幕：建议宽度 360 像素及以上，支持桌面与手机访问
- 无需安装额外插件或客户端

### 2.3 依赖组件

- React 19、Vite 8
- Supabase Auth 与 PostgreSQL
- DeepSeek 文本接口、通义千问 VL 图像识别接口
- `docx`（生成源代码文档）、`sharp`（图片压缩，仅本地脚本使用）

## 三、功能说明

### 3.1 学生端

1. **账号登录**：使用学号与密码登录，首次登录的初始密码为学号；账号被停用时无法登录。
2. **思政成长画像测评**：完成 16 道主问卷题目，并根据作答出现 1 道引导题；提交后系统计算八个维度的得分与画像类型。
3. **八维画像展示**：以雷达图、维度进度条和文字说明展示专业认同度、使命感知度、价值定力、集体协同感、思辨开放度、报国信心、职业方向感、思政资源感知八个维度。
4. **画像卡片**：根据画像类型生成可保存的画像卡片，包含画像类型、维度分布与寄语。
5. **兵工案例学习**：按推荐顺序学习案例背景、图片资料、思政映射与引导问题；完成学习后写入学习行为记录。
6. **每日问题**：每天展示一道思政思考题，提交后记录一次学习行为；跳过不产生记录。
7. **AI 学习助手“小备”**：登录后可向小备提问；服务端校验身份与调用频率后转发至文本模型。
8. **装备图片识别**：学生可上传装备图片进行识别，上传前在浏览器内压缩；系统不保存图片与识别结果。
9. **历史测评**：查看本人历次测评的画像类型与高低维度。

### 3.2 教师端

1. **学生名单**：读取数据库中真实学生资料，显示姓名、学号、班级、专业与测评状态。
2. **检索与筛选**：按姓名或学号搜索，按班级、已测评/未测评筛选。
3. **学生画像**：查看单个学生的画像类型、画像描述、匹配信息、八维得分与高低维度。
4. **班级均值雷达图**：将学生个人画像与本班已测评学生均值叠加对比。
5. **学习行为统计**：显示测评次数、案例学习次数、每日问题提交次数与 AI 调用次数，并列出最近学习记录。
6. **AI 教学建议**：点击后根据该生画像生成教学参考建议，结果不写入数据库。
7. **名单导出**：将当前筛选结果导出为带 UTF-8 BOM 的 CSV 文件，可直接用 Excel 打开。

### 3.3 管理端

1. **学校数据看板**：展示覆盖学生数、完成测评人数与参与率、累计互动次数、案例覆盖数量。
2. **八维群体画像**：按学院全体学生计算八个维度的平均分，并给出优势维度与待关注维度。
3. **画像类型分布**：以环形图展示各画像类型人数与占比。
4. **班级与专业统计**：按班级、专业统计人数、已测评人数、参与率与主导画像。

6. **思政主题参与热度**：根据案例学习行为统计各思政主题的参与次数。
7. **AI 数据分析**：存在测评数据时可生成学院层面的教学参考分析。
8. **名单导出**：导出全校名单与测评状态 CSV。

## 四、操作流程

### 4.1 学生使用流程

1. 打开系统登录页，输入学号与密码。
2. 首次登录且无测评记录时，进入思政成长画像测评。
3. 完成全部题目后提交，等待画像生成。
4. 查看画像结果、八维得分与推荐案例。
5. 进入推荐案例，阅读案例内容并完成引导问题。
6. 点击“标记本案例学习完成”，系统写入学习记录。
7. 可在画像页查看历史测评、完成每日问题或使用小备问答。

### 4.2 教师使用流程

1. 使用教师登录名与随机密码登录，进入教师数据面板。
2. 在名单中搜索或筛选学生。
3. 选择学生查看画像、班级均值与学习记录。
4. 需要时点击“生成建议”，获取该生的教学参考。
5. 点击“导出名单数据”，保存当前筛选结果。

### 4.3 管理员使用流程

1. 使用管理员登录名与随机密码登录，默认进入学校数据看板。
2. 查看学院总体指标、八维均值、类型分布、班级与专业统计。
3. 需要时点击“生成分析”，获取学院层面的教学参考。
4. 可切换到教师数据面板，查看单个学生画像。
5. 点击“导出名单数据”，保存全校名单与测评状态。

### 4.4 首次部署流程

1. 在 Supabase SQL Editor 执行 `supabase/migrations/001_init.sql`。
2. 在本地 `.env.local` 填写项目地址、公开密钥与服务端密钥。
3. 运行 `npm run import:roster` 导入学生名单。
4. 运行 `npm run staff` 创建教师与管理员账号。
5. 在 Vercel 配置环境变量并重新部署。
6. 使用管理员账号登录完成验收。

## 五、系统架构

本软件采用前后端分离结构：

- **浏览器端**：React 单页应用，负责登录、测评、画像展示、案例学习与数据看板。页面不直接创建 Supabase 客户端，所有数据访问集中在 `src/api/`。
- **服务端接口**：Vercel Serverless Functions 位于 `api/`，负责校验登录令牌与账号状态、限制调用频率，并代理 DeepSeek 与通义千问请求。AI 密钥仅存在于服务端环境变量。
- **数据库**：Supabase PostgreSQL 保存账号资料、测评结果与行为记录；行级安全策略保证学生只能读取自己的数据，教师与管理员可读取全部学生数据，客户端不能修改角色或资料。
- **登录映射**：登录名统一转换为 `登录名@users.bgzh.top` 后交由 Supabase Auth 处理，转换逻辑只保留在一处。

主要目录：

```text
src/pages/          登录页
src/views/          学生端、教师端、学校端
src/components/     业务组件、图表与弹窗
src/api/            前端数据访问与 Supabase 客户端
api/                Vercel Serverless Functions
api/_lib/           鉴权、校验、限频与管理客户端
supabase/migrations/数据库迁移脚本
scripts/            名单导入、账号创建、冒烟测试、报告与文档生成
```

## 六、数据与安全

1. **账号安全**：学生初始密码为学号；教师与管理员密码由脚本随机生成，只在终端显示并写入本地受保护文件，不进入代码仓库。
2. **权限隔离**：数据库启用行级安全策略。学生只能读取自己的资料、测评与行为记录；教师与管理员读取全部学生数据；客户端不能写入 `profiles`，不能修改或删除测评记录。
3. **AI 调用安全**：AI 接口要求携带有效登录令牌，并校验账号处于启用状态；图片识别仅限学生角色；消息数量、文本长度、图片类型与大小均在服务端校验；模型、温度与最大输出长度由服务端固定。
4. **调用频率**：同一账号每分钟最多调用 6 次、每天最多 60 次，超过后返回频率限制提示。
5. **隐私保护**：系统只记录行为类型、关联对象与时间，不保存 AI 对话内容、作答文字、上传图片或识别结果。教师端与学校端 AI 分析只接收聚合数据或画像维度，不传输学生姓名与学号。
6. **密钥管理**：`service_role` 与 AI 服务密钥只保存在本地 `.env.local` 与 Vercel 环境变量；前端只使用公开密钥；`.env.local`、学生名单与账号密码文件均被 Git 忽略。
7. **数据来源**：教师端与学校端的全部指标均由数据库实时汇总；无数据时显示“暂无”，不使用模拟数据或随机数。
